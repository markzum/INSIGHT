# Бизнес-пульс · фронтенд прототипа

Персональная новостная аналитика для руководителей крупного бизнеса в демонстрационной оболочке «Альфа-Бизнеса». Интерфейс связывает событие с признаками компании, объясняет возможные риски и возможности, показывает основания выводов и помогает сохранить следующий шаг.

Это интерфейс решения. Полный запуск парсера, дедупликации, агента и шлюза описан в корневом `README.md`: `docker compose up --build`, затем http://127.0.0.1:4173. Пустой `apiBaseUrl` оставляет учебный набор `data/demo.json`, где разборы подготовлены заранее и позиция банка намеренно не подставлена. При запуске через Docker сервер подставляет адрес шлюза, лента и разбор приходят от агента, а пометки демо скрываются.

## Запуск

Для фонового запуска дважды нажмите `START.cmd` или выполните из этой папки:

```sh
node scripts/local.cjs start
node scripts/local.cjs status
```

Адрес сайта: `http://127.0.0.1:4173/#feed`. Сервер запускается без отдельного окна и работает до остановки или перезагрузки компьютера. Повторный запуск не создаёт второй процесс. Для остановки используйте `STOP.cmd` или `node scripts/local.cjs stop`. Логи находятся в `.runtime/`.

Сервер отдаёт рабочие исходники: после изменения кода достаточно обновить страницу. Для обновления автономной версии `dist` выполните сборку. При переходе с `file://` на HTTP браузер использует отдельное localStorage; старые отметки не переносятся автоматически.

Требуется Node.js 22 или новее; версия указана в `.node-version`. Внешние пакеты для запуска не нужны.

```sh
node scripts/serve.cjs
```

Откройте `http://localhost:4173`. Сервер слушает локальный интерфейс. Команды выполняются в каталоге проекта.

```sh
node scripts/build.cjs
node --test tests/*.test.cjs
```

Сборка формирует `dist/`. Для автономного просмотра можно открыть `dist/index.html` двойным щелчком: JavaScript-версия fixture используется без сетевого запроса. Предпочтительный способ проверки — локальный сервер, поскольку поведение хранения данных для `file://` зависит от браузера.

При установленном npm доступны `npm start`, `npm stop`, `npm run status`, `npm run dev`, `npm run build` и `npm test`; установка зависимостей не требуется. Для PowerShell при ограничении запуска `.ps1` используйте `npm.cmd` или прямые команды `node`.

Проверены модель данных, сборка и синтаксис JavaScript. Визуальная и интерактивная проверка в настоящем браузере не выполнена: механизм безопасности браузера приложения явно запретил доступ к локальному адресу. Скриншоты не создавались. Состав проверок и ограничения описаны в [docs/VERIFICATION.md](docs/VERIFICATION.md).

Для запуска статического фронтенда в Docker предусмотрены `Dockerfile` и `compose.yaml`:

```sh
docker compose up --build
```

Откройте тот же адрес `http://localhost:4173`. Сборка контейнера запускает сборку сайта и тесты; сам Docker должен быть установлен отдельно. Контейнер содержит только фронтенд, без API и моделей. Docker-запуск при подготовке этого комплекта не выполнялся.

## Сценарий демонстрации

1. Откройте обзор компании. Проверьте метку деморежима, выбранную компанию и роль пользователя; перейдите в «Бизнес-пульс» через постоянно доступную навигацию или карточку обзора.
2. Просмотрите приоритетные события и объяснение их связи с компанией. Переключите компанию и роль: сравните состав и порядок ленты, а также объяснение релевантности. Оценки в fixture редакционные; они не являются вероятностью или результатом работающей модели.
3. Нажмите «Разобрать влияние». Во вкладке «Разбор» последовательно изучите сведения из демонстрационного источника, отсутствие банковской позиции и отдельно обозначенную интерпретацию. Откройте «Основания и допущения», затем вкладку «Риски и возможности».
4. Перейдите во вкладку «Источники и проверка» и нажмите «Читать исходный текст». Сопоставьте событие с конкретными признаками компании. У вымышленных материалов нет реальной ссылки на оригинал.
5. В той же вкладке просмотрите блоки «Проверка полноты» и «Как подготовлен разбор». Они иллюстрируют будущий процесс, но не подтверждают выполнение агентной системы.
6. В блоке «Разобраться глубже» выберите предложенный уточняющий вопрос. Ответ помечен как заранее подготовленная демонстрация. Произвольный вопрос вне fixture сообщает об отсутствии подключенного AI.
7. Нажмите «Сохранить событие». Во вкладке «План действий» отметьте один шаг выполненным и оставьте оценку «Этот разбор полезен?». Проверьте разделы «Сохранённое» и «План действий», затем обновите страницу: локальные отметки сохраняются в этом браузере. Все предложенные шаги уже включены в план; он не отправляет поручения сотрудникам.
8. Проверьте интерфейс на узком экране и с клавиатуры: переход по основным ссылкам, выбор контекста, вкладки, диалоги и возврат к контенту.

Для проверки состояний откройте «Как устроено демо» в навигации → «Проверить состояние интерфейса», выберите вариант и нажмите «Показать состояние». Доступны обычная демонстрация, загрузка, отсутствие событий, ошибка загрузки и нехватка данных. Из загрузки можно выйти кнопкой «Завершить демонстрацию загрузки», из ошибки — повторить запрос. Для возврата к исходному набору выберите «Обычная демонстрация».

Состояния также задаются параметром URL: `?state=loading`, `?state=empty`, `?state=error`, `?state=partial`. Неполнота банковской аналитики остается явно обозначенной и в обычном демо.

## Архитектура и файлы

- `index.html`, `assets/` — оболочка, маршрутизация, представление и клиентская логика на обычных JavaScript/CSS.
- `data/demo.json` — единственный редактируемый источник синтетических данных; `types.d.ts` описывает fixture v3.
- `scripts/build.cjs` — сборка статического сайта и генерация `dist/data/demo-data.js` из JSON для автономного запуска.
- `scripts/serve.cjs` — локальный сервер для разработки; `tests/` — проверки модели данных и изолированные проверки клиентской логики.
- `docs/API.md` — граница API и условия перехода к реальным данным; `docs/REVIEW.md` — аудит и покрытие требований кейса.
- `docs/VERIFICATION.md` — выполненные проверки и список того, что требует настоящего браузера.
- `THIRD_PARTY_NOTICES.md` — компоненты, происхождение материалов и смоделированные интеграции.

Маршруты: `#overview`, `#feed`, `#saved`, `#actions`, `#company`, `#insight/{id}/{tab}`. Выбор компании и роли, прочитанность, закладки, действия и обратная связь сохраняются локально. Это состояние одного браузера, а не учетная запись или серверный журнал.

## Настройка API

До загрузки приложения можно задать:

```js
window.ALFA_CONFIG = {
  apiBaseUrl: '',
  requestTimeoutMs: 10000
};
```

Пустой `apiBaseUrl` включает локальные демоданные. Непустое значение включает запросы к шлюзу: рабочее пространство, уточняющий вопрос и отзыв о полезности. Форматы описаны в `docs/API.md`. Шлюз, агент, парсер и дедупликация живут в соседних каталогах репозитория и поднимаются вместе из корня.

Ключи моделей остаются на сервере агента. Браузер их не видит.

## Итог проверки

32/32 автоматических проверок прошли: 13 тестов модели и 19 проверок приложения с заменённой браузерной средой. Сборка и синтаксические проверки успешны. Реальная браузерная проверка заблокирована настройкой доступа к локальному адресу; визуальное качество, геометрия адаптивных экранов и поведение настоящего DOM остаются непроверенными. Подробности и чек-лист: `docs/VERIFICATION.md`.
