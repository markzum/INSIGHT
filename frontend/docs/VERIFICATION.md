# Проверка и ограничения

Ниже — проверка интерфейса на учебном наборе. Сквозной запуск всего решения описан в корневом `README.md`. Разделы, где сказано, что агента и парсера нет, описывают отдельную проверку фронтенда и устарели относительно текущей поставки.

## Что выполнено

- Проверена логика модели данных тестами Node.js: персонализация, ранжирование, фильтрация, состояния неполноты и обработка некорректных данных.
- Выполнена сборка статических файлов и проверка синтаксиса JavaScript.
- Проведен разбор кода маршрутизации, сохранения локального состояния, разделения происхождения материалов и обработки неполных данных. Найденные проблемы исправлены в исходниках.
- Проверены CSS-правила адаптации для границ 700, 1000, 1200 и 1600 px, а также отключения анимации при `prefers-reduced-motion`.

Команды для повторения:

```sh
node scripts/build.cjs
node --test tests/*.test.cjs
node --check assets/model.js
node --check assets/app.js
```

Изолированные проверки приложения через Node VM проверяют клиентскую логику с замененными объектами браузерной среды. Они не проверяют настоящий DOM, CSS-геометрию, браузерную доступность или фактическое поведение диалогов. Итоговый запуск 22 октября 2026 года: 32 из 32 тестов пройдены (13 тестов модели и 19 проверок приложения в изолированной Node VM), ошибок нет. Проверено на Node.js 24.19.0. Сборка и проверки синтаксиса также завершились успешно.

## Что не проверено

Механизм безопасности браузера приложения явно запретил доступ к локальному адресу сервера. Повторная попытка после обновления разрешений также отклонена: сохранённая настройка разрешений или управляемая политика блокирует этот адрес. После отказа браузерная проверка не проводилась: **нет скриншотов, результатов реальных кликов, измерения переполнения или подтверждения визуального качества на экранах разных размеров**. Все исходные файлы и тестовые данные оставались локальными; сайт не публиковался во внешний сервис для обхода ограничения.

Docker-запуск не выполнялся. Внешний API, авторизация, RAG, парсер, LLM и агентный процесс отсутствуют, поэтому интеграционная проверка этих компонентов не проводилась. Наличие адаптера API не означает готовности интерфейса к производственным данным.

## Чек-лист для настоящего браузера

Следующие пункты остаются непроверенными. Запустите `node scripts/serve.cjs` и откройте `http://localhost:4173` в обычном браузере.

| Размер | Что проверить |
| --- | --- |
| 390 px | Нет горизонтального переполнения страницы; доступны навигация, выбор компании и роли, фильтры, вкладки и кнопки; диалог помещается на экране |
| 768 px | Карточки и боковые блоки корректно перестраиваются; длинные заголовки не перекрывают управление |
| 1440 px | Читаемая ширина текста, согласованная сетка, отсутствие лишних зазоров и обрезанного содержимого |

- Пройти обзор → лента → смена компании и роли → разбор → источник → вопрос → сохраненное событие → отметка действия.
- Проверить загрузку, пустую выдачу, ошибку с повтором и неполные данные через «Как устроено демо».
- Пройти сценарий только клавиатурой: пропуск навигации, порядок Tab, видимый фокус, стрелки/Home/End во вкладках, Escape в диалоге и возврат фокуса после закрытия.
- Проверить объявления статусов экранным диктором, имена элементов управления, контраст и увеличение масштаба до 200%.
- Проверить сохранение выбранного контекста, закладок и отметок после перезагрузки; отдельно проверить ограниченное или недоступное хранилище браузера.
- Открыть `dist/index.html` без сервера и проверить автономный путь, учитывая особенности `file://` и локального хранения в выбранном браузере.

Размеры 390, 768 и 1440 px — целевые точки проверки, а не размеры уже проверенных скриншотов.
